GLOOPRINT WINDOWS RELEASE VALIDATION
UE 5.8 | 1.0.0-rc1 | Windows 64-bit

Use the exact candidate archive and record its SHA-256 before testing. Native
C++ packaging and desktop behavior are separate checks. A Blueprint compile
does not validate C++, and a successful editor exit does not prove tests passed.

The WindowsTestKit ZIP is a convenience handoff: extract it to C:\ to create
C:\GlooPrintRC with the plugin source, a ready TestHost descriptor and this
guide. Skip the separate host-copy step below when using that kit. Do not upload
WindowsTestKit to Fab; the separately named Source ZIP is the submission file.

1. BUILD THE CANDIDATE

Install UE 5.8 and its supported Visual Studio C++ toolchain. Extract the
candidate Source ZIP to a short path such as C:\GlooPrintRC. It should contain
C:\GlooPrintRC\GlooPrint\GlooPrint.uplugin. Do not use the Mac build binaries.

In PowerShell, adjust the first two paths and use a NEW package output path:

    $GlooEngine = 'C:\Program Files\Epic Games\UE_5.8'
    $GlooSource = 'C:\GlooPrintRC\GlooPrint'
    $GlooPackage = 'C:\GlooPrintRC\BuildWin64'
    & "$GlooEngine\Engine\Build\BatchFiles\RunUAT.bat" BuildPlugin "-Plugin=$GlooSource\GlooPrint.uplugin" "-Package=$GlooPackage" -Rocket -StrictIncludes -HostPlatforms=Win64 -TargetPlatforms=Win64
    if ($LASTEXITCODE -ne 0) { throw 'BuildPlugin failed; preserve the log and fix the first error.' }

Keep the entire build log. Require no plugin compilation errors or consequential
warnings. BuildPlugin checks the installed-engine workflow Fab uses. It should
preserve Source, Resources/Icon128.png and Documentation/UserGuide.txt.

Alternatively, with a repository checkout and Python 3.9+:

    py -3 Scripts\PrepareRelease.py --output C:\GlooPrintRC\ReleaseWin64 --engine-root "$GlooEngine"

This preserves a source inventory and the BuildPlugin log automatically.
Do not submit the BuildWin64 folder: Epic wants the source-only submission ZIP.

2. INSTALL AS AN ENGINE PLUGIN

With the editor closed, copy the CONTENTS of BuildWin64 into the new folder
UE_5.8\Engine\Plugins\Fab\GlooPrint. If GlooPrint already exists there, preserve
that installation and use an isolated UE installation for the release check.
Never keep duplicate engine/project installations. Enable GlooPrint in a new
disposable project. Check the Plugins window shows the expected candidate
version, publisher, icon, documentation and support links. Confirm the log
loads the candidate GlooPrint binary from this engine installation.

Test both a new Blueprint-only project and an existing C++ project copy. The
plugin should not require adding C++ to a Blueprint-only consumer project.

3. RUN THE EXISTING NATIVE TESTS

Use a disposable host; automation creates, opens and closes Blueprint editors
and can save its own fixtures. Keep normal rendering enabled; do not use
-NullRHI or UnrealEditor-Cmd for the Slate interaction suite. Avoid other work
in the test editor during the run.
The complete suite includes large native benchmarks and can take tens of
minutes. Track the current log; do not launch a second run while it is active.

Copy Tests/HostProject/GlooPrintHost.uproject from the repository to an empty
C:\GlooPrintRC\TestHost folder (do not copy its Plugins or Saved folders).
The following command tests the engine-installed candidate:

    $GlooHost = 'C:\GlooPrintRC\TestHost\GlooPrintHost.uproject'
    & "$GlooEngine\Engine\Binaries\Win64\UnrealEditor.exe" $GlooHost -unattended -nosplash '-ExecCmds=Automation SetFilter Engine,Automation RunTests GlooPrint.' '-TestExit=Automation Test Queue Empty' '-ReportExportPath=C:\GlooPrintRC\TestHost\Saved\FabRelease' '-abslog=C:\GlooPrintRC\TestHost\Saved\FabRelease.log'

Wait for the editor to close. Inspect Saved\FabRelease\index.json, including
failed, notRun, inProcess and individual test entries. Zero executed tests is
not a pass. Preserve the report, log and screenshots, and investigate every
failure or consequential warning. Performance tests report measurements;
passing automation does not close the open responsiveness acceptance item.

4. DESKTOP ACCEPTANCE

For both rounded and 45-degree styles, record PASS/FAIL and a screenshot or
short video for these checks in a small representative graph:

[ ] F formats the full active graph, including disconnected nodes; the
    selected anchor stays fixed. Other graphs, selection, camera and zoom stay
    unchanged. Comments and existing reroutes are preserved.
[ ] F in a text field edits text. Other windows, Details panels, search boxes,
    read-only graphs, PIE and Blueprint breakpoints do not trigger formatting.
    Context menu and a rebound shortcut work as described.
[ ] Undo restores exact layout and comment bounds in one step; Redo restores
    the format. Repeated F on the unchanged layout adds no undo/dirty state.
[ ] All original links, pin defaults and behavior remain; compile succeeds.
    Save, close the editor, reopen, compile and check the saved layout again.
[ ] Wires attach at pins while dragging, panning and zooming, including when
    endpoints are offscreen. Colors and execution highlighting work in PIE
    and at a breakpoint. Hover targets the visible wire.
[ ] Double-click inserts a native reroute on the visible wire; undo/redo is
    correct. Native Alt break/slice and Ctrl reconnect work. Start Shift
    connections from the pin (the native wire-first limitation is documented).
[ ] A slow format can be cancelled using the physical mouse; no partial layout
    or undo entry appears. Changing focus, deleting/reconstructing nodes, or
    closing the tab during preparation does not crash or apply stale results.
[ ] Settings survive restart. Formatting off and Native style restore native
    behavior. Plugin disabled on restart leaves saved Blueprints editable,
    compilable, and connected, including native wire gestures.
[ ] Windows display scales 100%, 125%, 150%, 200% and a mixed-DPI monitor move
    retain correct geometry/hit testing at supported zoom levels. Test the
    physical configurations you intend to support; record any unavailable.
[ ] Supported K2 graphs work: Event, function, macro, Construction Script,
    opened collapsed, pure-data and Animation Blueprint Event Graph. Unsupported
    Material/animation-pose/Niagara/Control Rig graphs retain native behavior.
[ ] In a disposable copy, package a small Development and Shipping game with
    GlooPrint enabled. The editor-only module must not become a game dependency.
[ ] Review a branch/join, nested comments, shared pure inputs and a dense graph
    for actual readability. Record graph size and pauses for large cases; do
    not advertise a fixed timing or zero-crossing guarantee.

If using another formatter/wire plugin, explicitly test coexistence or retain
the documented conflict limitation. Do not silently skip a failing check.

5. REPORT AND FINALIZE

Record Windows/UE/plugin versions, CPU/RAM/GPU, display scale, archive hash,
build result, automation report path, manual results and known limitations.
Send the build log and reproduction steps for any failure. Update the candidate
only after fixes, then repeat the affected checks on the final source state.

After both platform checks pass, remove candidate/pending-testing wording from
customer documentation and the Fab draft, choose the final release version,
regenerate the source ZIP and record its hashes. Descriptor/docs-only changes
do not require repeating unaffected native tests. Keep the source-only ZIP
available through a reviewer-accessible hosting page. Complete remaining Fab
fields, preview the listing, and submit only when ready for review.
